# 第五章 agent 产品体验思考：Hermes 的三个聪明设计

## 1. 视角说明

前面几章从"实现者"视角看 agent：第一章拆执行引擎，第二章剖析记忆机制，第三章造读码工具。这一章换一个视角——**产品体验视角**：一个 agent 要真正好用，除了核心机制正确，还有哪些产品层面的设计？我以 Hermes 为例，讲它最聪明的三个设计：**多平台接入、自动学习和沉淀 skill、记忆挖掘**。

这三个点不是"功能清单"，而是"产品哲学的体现"——它们回答的都是同一个问题：**agent 怎么在不打扰用户的前提下，持续变得更懂用户、更有用？**

## 2. 亮点一：多平台接入——一套核心，处处可及

**现象**：Hermes 可以接入多个平台（飞书、Telegram、Discord 等），用户在哪里，它就在哪里。核心逻辑只有一套，平台只是外壳。

**为什么这是聪明的设计**：

1. **核心与适配分离**。agent 的执行循环（第一章的核心）与平台适配（消息收发、格式转换）解耦——新接一个平台，只写适配层，不动核心。这是"核心窄腰，能力在边缘"架构思想的产品化体现。
2. **降低使用门槛**。用户不需要打开某个专门的应用才能用 agent——在已经习惯的聊天软件里就能对话。**产品适应人的习惯，而不是要求人适应产品**。
3. **跨平台上下文连续**。同一个 agent、同一份记忆，在飞书聊到一半，换到 Telegram 可以继续。平台的切换对用户透明，这依赖第二章讲的记忆机制做底座。

**我的认知**：多平台接入看似是"工程活"（写适配器），本质是产品决策——**它把 agent 从"一个应用"变成了"一种能力"**。用户感知到的不是"某个平台的 bot"，而是"随时可用的助手"。

## 3. 亮点二：自动学习和沉淀 skill——用过的经验不丢失

**现象**：Hermes 会把使用中的经验自动沉淀成 skill（技能文件）——踩过的坑、总结出的流程、发现的工作方法，形成可复用的技能，下次遇到同类任务直接调用。

**为什么这是聪明的设计**：

1. **把"经验"变成"资产"**。人的经验存在大脑里，agent 的经验存在 skill 文件里。自动沉淀让 agent 的成长不依赖单次会话——这次学会的，下次还在。
2. **技能是可检索、可共享的**。skill 不是藏在代码里的逻辑，而是结构化的文档（SKILL.md），可被查看、被编辑、被其他会话复用。经验的表达是开放的。
3. **自动沉淀解决了"记不住"的痛点**。用户不需要主动告诉 agent"你应该记住这个工作方式"——agent 自己在使用中识别值得沉淀的模式，后台完成。

**我的认知**：自动学习 skill 是 agent 产品"自我进化"的温和形态——**不改变核心代码，只通过积累技能文件，agent 就能越来越擅长用户的领域**。相比频繁发版升级，这种"使用中成长"的产品形态更轻、更贴合个人用户。

## 4. 亮点三：记忆挖掘——主动记住用户的细节

**现象**：Hermes 会在对话过程中主动挖掘用户透露的信息（身份、偏好、项目背景），写入记忆文件（MEMORY.md / USER.md），并在后续对话中复用——用户不用重复介绍自己。

**为什么这是聪明的设计**：

1. **把"记住"从用户任务里拿掉**。好的产品不让用户做产品该做的事。让用户每次对话都重新自我介绍，是把记忆负担推给用户；自动记忆挖掘把这个负担接了过去。
2. **记忆是分层、有界的**。不是把所有对话都存下来，而是挖掘"值得记的"（身份、偏好、原则），且有容量上限——**记忆的价值在于精，不在于多**（这正是第二章讨论的主题）。
3. **不打扰**。记忆挖掘在后台完成（每 N 轮一次反思），不打断对话；用户看到的效果只是"agent 越来越懂我"，不需要任何操作。

**我的认知**：记忆挖掘是三个亮点里最"润物细无声"的——**用户几乎感知不到它的存在，但持续受益于它的效果**。一个 agent 是否"聪明"，很大程度上取决于它能不能自己记住该记的、忘掉该忘的（第二章的取舍判断），而不是用户反复教它。

## 5. 小结：三个亮点背后的共同产品观

三个亮点表面上是不同功能，底层是同一条产品线：

| 亮点 | 解决的用户痛点 | 底层机制 |
|---|---|---|
| 多平台接入 | 用户不想为了用 agent 换工具 | 核心/适配分离 |
| 自动沉淀 skill | 用户的经验不想每次重来 | 技能文件化 + 自动识别 |
| 记忆挖掘 | 用户不想重复自我介绍 | 后台反思 + 分层记忆 |

共同的产品观是：**agent 应该主动适配用户，而不是要求用户适配 agent**。多平台接入让 agent 出现在用户习惯的地方；skill 沉淀让 agent 记住用户的工作方式；记忆挖掘让 agent 记住用户的身份和偏好——三个方向都是"把负担从用户身上拿走，接过来自己扛"。

这也是我判断一个 agent 产品是否成熟的标准：**看它把多少"本该用户做的事"变成了"自己主动做的事"**。
