## ① #79788 · 快递地址被"好心"改写（fallback URL 重写）

你平时用 DeepSeek 这个快递公司收发模型消息。某天 DeepSeek 堵车（限流），系统自动切到备用快递——阿里云的 Qwen，地址明明写的是"…/anthropic 大厦"。结果包裹发出去后 404 找不到：系统里有个"地址改写员" `_to_openai_base_url`，它看到 `/anthropic` 结尾就一律改成 `/v1`——因为它默认所有备用快递都是 OpenAI 格式的，遇到用 Anthropic 格式的备用公司就乱改。结果：主快递一堵车，备用快递也全灭。

## ② #84667 · 同一张门禁卡，大门能刷侧门不能（cron 加载 skill）

你有一张叫 skill-review-gate 的门禁卡。走大门（`hermes --skills` 命令）刷，门开了，正常工作。把同一张卡挂到 cron 侧门（定时任务）上，系统却说"查无此卡"。你做了全套体检：卡在口袋里、编号正确、磁条完好（`hermes skills list` 显示 enabled）——一切正常。原因是**两条代码路径的读卡器不是同一个**：CLI 入口和 cron 入口调用了不同的 skill 解析路径，一条能找到 skill 目录，另一条没走那条路。同一个人，两个入口，一个认识你一个不认识你。

## ③ #84233 · 水龙头开了不关（state.db 连接泄漏）

仪表盘进程像一间 44 小时没关门的茶水间：每处理一次会话就开一个新水管（数据库连接），**用完从不关上**。水管越积越多，到 50 根时把房间 256 个水龙头口全占满了——这时候想再开新水管（启动子进程）就报"没水管口了"（Errno 24: Too many open files）。重启进程，水管从 50 根掉回 8 根，一切恢复正常。原因：连接打开了，对应的 close 没人负责，也没有连接复用池。

## ④ #85135 · 外卖等 8 秒没到，就当没点过（memory 预取超时写死）

你让 agent 从外部记忆库（Honcho）翻"上次聊到哪了"。记忆库冷启动翻东西要 9~11 秒，但系统只肯等 **8 秒**——超时就直接当"没有记忆"，**静默放弃**。结果 agent 表现得像个失忆症患者，日志里还看不出任何异常。最气的是：代码里构造函数明明支持自定义等待时长，但实例化时**没人把配置传进去**，8 秒被写死。你只能在本地打补丁，每次升级都要重新打。

## ⑤ #85564 · 第一次进小区门总是迟到（飞书首次连接超时）——🎯 飞书相关

飞书 bot 冷启动时，首次连接要花 **24 秒**加载 SDK（lark_oapi 库），但平台给的连接时限默认是 **30 秒**——这还不算其他启动开销，一算就超了。超时后重试只要 1 秒（库已经加载进内存了），所以 bot 通常能自愈。**但**如果在重试前进程被杀——比如 Hermes 更新后自动重启——bot 就一直离线。用户看到的现象就是"**更新完飞书 bot 就不说话了**"，要手动重启才恢复。

## ⑥ #85524 · 失忆的翻译（中文 memory 预取静默失败）——🎯 中文相关

你存了一堆中文记忆（"微信数据目录"、"SMB NAS 环境"）。每次对话 agent 都会自动回忆一次，但检索器分词是**按空格切的**——中文没空格，你问"我们现在的记忆提供商是？"整句被当成**一个词**，和索引里的词永远对不上，每次 0 命中。agent 表现得完全失忆，还不报错。原因：英文空格分词的假设，对中文/日文/韩文这种不分词语言全部失效。

## 小结（发过的那版收尾）

6 个里有 3 个是"静默失败"家族（③连接泄漏无声无息、④记忆预取超时静默、⑥中文检索静默）——这类最坑，因为不报错、难发现。⑤是飞书专属，日常用飞书的用户随时可能踩到。
